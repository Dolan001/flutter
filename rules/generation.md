# Generation rules

- Inspect before generation and preserve compatible target conventions.
- Resolve stable supported Flutter/Dart and plugin versions at execution time.
- Generate the smallest requirement-backed vertical slice.
- Never copy runnable application code from this behavior pack.
- Implement approved design evidence accessibly across supported device classes.
- Keep native code minimal and never generate secrets or signing credentials.
- Resolve feature and file names from PRD product language; use familiar capability vocabulary only
  when unnamed, never vague architecture labels.
- Name Dart files by responsibility and split feature layers at the contract's 250-line boundary.
