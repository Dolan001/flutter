# Implement Flutter vertical slice

Implement one cohesive feature through data, domain, application, and presentation
boundaries. Match approved design while adapting interaction to Android and iOS
conventions. Validate network and persisted data, expose typed failures, handle loading,
empty, offline, error, authorization, retry, restoration, and success states, and add
unit, widget, golden, and integration coverage appropriate to the change.

Map requirement IDs to familiar feature, page, widget, state, use-case, repository, and data-source
names before writing. Prefer explicit PRD vocabulary and justify any conventional fallback. Split
each layer by responsibility before a Dart source file exceeds 250 lines.

Read `references/production-delivery.md` for state, API, security, accessibility,
platform, performance, test, and release rules. Stop for independent verification.
